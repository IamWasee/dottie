## Overview

Dottie is a macOS menu bar companion app with every AI call on Google Gemini's free tier. Lives entirely in the macOS status bar (no dock icon, no main window). Clicking the menu bar icon opens a custom floating panel with companion voice controls. Push-to-talk (ctrl+option) streams the user's voice and one frame of their screen(s) to Gemini Live, which answers in streamed audio. A blue cursor overlay can fly to and point at UI elements Gemini picks via a tool call, on any connected monitor.

The only key is a Gemini API key, and it lives on a Cloudflare Worker proxy — nothing sensitive ships in the app. See ROADMAP.md for which features exist so far.

## Architecture

- **App Type**: Menu bar-only (`LSUIElement=true`), no dock icon or main window
- **Framework**: SwiftUI (macOS native) with AppKit bridging for menu bar panel and cursor overlay
- **Pattern**: MVVM with `@StateObject` / `@Published` state management
- **Voice companion (live mode, default)**: Gemini Live (`gemini-3.8-live`) over a WebSocket opened with a single-use ephemeral token from the Worker. Manual activity detection: hotkey press sends `activityStart` + a JPEG frame, release sends `activityEnd`. Output is 24kHz PCM played as it streams. Pointing is the `point_at_element` tool (0–1000 coordinates on the frame). Only about 20 everyday tools are declared (`GeminiLiveToolCatalog.directFunctionNames`); the rest are found with `find_tool` and run with `use_tool` through the same dispatch, so a rarely used tool's how-and-when belongs in its description, not the voice prompt.
- **Classic mode (`CompanionVoiceMode=classic`)**: Apple Speech → Gemini Flash vision (SSE via Worker `/chat`) → Gemini TTS (Worker `/tts`), with `[POINT:]` tags
- **Background agents ("Dots"; "Clickys" in type names)**: each agent turn runs Google's Gemini CLI headless (`gemini -p … -o stream-json --approval-mode yolo`, `--session-id` then `--resume`) in the agent's folder under `~/Library/Application Support/Dottie/Dots/<slug>/`. `GOOGLE_GEMINI_BASE_URL` points it at the Worker's `/gemini` passthrough and `GEMINI_CLI_HOME` at an app-owned `.cli-home`, so the user's own `~/.gemini` is untouched. Live hands work over with the `start_clicky_task` tool; results show as a notch card.
- **Skills**: a library of Gemini CLI skills (`SKILL.md` folders) in `~/Library/Application Support/Dottie/Skills/`. Each agent's enabled skills are symlinked into its workspace's `.gemini/skills/` before each turn, and the library is passed with `--include-directories` so agents can save new skills there (the app turns a skill an agent saved on for that agent).
- **Routines**: agents set up repeats by ending a reply with `<ROUTINE>{"action":"create","every_minutes":60,"title":…,"task":…}</ROUTINE>` (also update, delete, pause, resume). `ClickyRoutineStore` keeps them in `Dots/routines.json`; a 30-second timer in `ClickyRoster` runs due ones while the Mac is awake and online. Every user turn starts with the agent's current routine list; run turns get a "report what's new" brief. Three failed runs in a row pause a routine. Runs keep their own conversation (fresh every 8 runs, carrying the last report) and run on Gemini, except 24/7 jobs; a reply of exactly `NOTHING NEW` stays quiet and doubles the wait (up to 60 minutes, back to the set pace on a change). An optional `watch_url` is read first and the run skipped while its text is unchanged. A Dot's chat with the user starts a fresh session, with a 6-message handover, after 45 idle minutes or 12 turns.
- **Computer use**: the app target's "Embed cua-driver" build phase runs `scripts/embed-cua-driver.sh`, which puts a pinned, checksum-verified cua-driver release in `Contents/Helpers/cua-driver` (cached in ~/Library/Caches/Dottie-build; offline builds just warn). To update it, bump `CUA_DRIVER_VERSION` in that script. When the driver is found (bundled first, then ~/.local/bin), it's registered in Gemini CLI's settings as two MCP servers, `computer-use` (looking tools only) and `computer-use-act` (looking and input tools), both `cua-driver mcp --direct --embedded` so they inherit the app's permissions; each turn gets only one of them through `--allowed-mcp-server-names`. Each turn sets `CLICKY_CUA_POLICY_FILE` to a look-only or look-and-act policy; act is used only for turns the user allowed or with "Always allow". Agents ask with a `<COMPUTER_USE_REQUEST>` block, which becomes an Allow / Always / Not now card.
- **Instant lane (no AI)**: in live mode `GeminiLiveCompanionTranscriptionProvider` also feeds each push-to-talk turn to Apple's speech recognizer (`DictationLiveTranscriber`, only when Speech Recognition is already allowed). On release, if the words might be instant, Live's answer audio and tool calls are held (`isHoldingModelAnswer`) for up to 0.6 s while `DottieInstantLane` checks the final text; a match cancels Live's answer and the Mac does it. Typed and classic turns are checked the same way before Gemini. Instant commands (`DottieInstantCommands`) are open/quit app, move windows, music, volume, Google/YouTube searches, everyday keyboard shortcuts by name ("minimize" → cmd+M, "new tab", "undo", …) and keys said out loud ("press command shift T"). Learned shortcuts: a Live turn whose tool calls were all replayable (`open_url`, `press_keys`, `run_shortcut`, safe `run_applescript`, `control_device`) is saved under the user's words and replayed without Gemini next time; "when I say X, Y" names one, and "minimize means command M" teaches a key. A turn that only pressed keys is learned even from one word or with "this". Ideas from Atticus (MIT).
- **Needle (on-Mac model, no AI service)**: Cactus Needle 3 and Whistle (Apache-2.0) run inside the app. `scripts/embed-needle.sh` (build phase "Embed Needle") puts a pinned, checksum-verified universal `libneedle3.dylib` in `Contents/Frameworks` and `needle3.cact` / `whistle.cact` in `Contents/Resources/Needle`; `DottieNeedleEngine` opens them with dlopen (nothing happens if they're missing). When the strict lane doesn't match, `DottieNeedleRouter` asks Needle for a tool call from a ≤5-tool set chosen by the ask's words (`DottieNeedleToolset`: apps/windows, music/volume, search, reminders/calendar), acts only when the confidence is high enough and the user's own words back the call up, turns it into instant command words parsed strictly as usual (or Dottie's own `add_reminder` / `add_calendar_event`, times read by `NSDataDetector`), and saves the ask as a learned shortcut. It also does Mac actions when Gemini can't be reached, nudges `find_tool` by meaning (centered vectors), and, when Speech Recognition isn't allowed, Whistle hears short push-to-talk turns (`DottieWhistleTurnRecorder`). The Needle lab workflow (`scripts/needle-lab`) runs the same Swift code against the real engine on a Mac runner; rerun it after changing the toolsets or bumping the version.
- **Working on its own**: screen jobs think with Claude Sonnet through MausBot (`DottieScreenJobClaudeBrain`: the runner's newest turn becomes one message with the screenshot as a file, Claude answers JSON actions with pixel boxes that become Gemini function-call parts with the placeholder thought signature; after one miss the rest of the job runs on Gemini). Before any screenshot, `DottieScreenJobGuesser` asks for the steps in words (menus by path, shortcuts, controls by name, links) and does them through Accessibility, finishing without a screenshot when the done text shows on-Mac OCR, else handing over with a note. `DottieWatchAndLearn` ("watch me for 30 seconds") keeps frames plus the smart-replay action lines and has Claude write a how-to (goal, method, where things are), saved in `Watched/howtos.json` and as a library skill for every Dot; screen jobs read matching how-tos. Away mode (`DottieAwayMode`) sends questions, helper computer-use requests and any click on a pay/send/post/delete button (checked on the Mac) to Telegram with Allow / Deny buttons (`DottiePhoneBridge.ask`), never passwords; it retries a failed job once with a different route, texts results and failure screenshots, and logs everything for the "while you were away" report. Helpers get `DottieWorkRoutes.helperInstructions` (connected apps/APIs, then CLI/AppleScript, then the user's browser, then a `<SCREEN_JOB>` block Dottie runs with the result sent back to the helper; Word/Excel files; saving new kinds of tasks as skills) and, unless turned off, the user's Documents, Desktop and Downloads. Shared Claude bots go through `DottieClaudeBot`.
- **Connectors**: Home → Tools also lists sign-in connectors like Claude's (hosted MCP servers through `npx mcp-remote`, OAuth in the browser, 300 s handshake), Roblox Studio's built-in MCP server, and "Bring in my Claude connectors" (Claude Desktop's config and `~/.claude.json`).
- **Code editor**: Home → Code (`HomeCodeView`, `DottieCodeWorkspace`) is a small editor over Projects, the Dots' folders and opened folders: NSTextView with regex colors, cmd+S, a command box run in the file's folder, "Ask Coder" (a helper), and reload when a helper changes the open file. Voice tool `code_editor`.
- **Notes board**: `write_notes` (`DottieNotesBoard`) opens a dark, non-activating notebook panel that scrolls both ways: headings, subheadings, paragraphs, bullet/numbered lists, one-line equations that never wrap, dividers and pictures (a screenshot, one part of the screen found like a drawing anchor, or a web picture/og:image). `place: right` continues the same row, otherwise a new row. Pages autosave as Markdown in `Application Support/Dottie/Notes/`. Text everywhere Dottie writes (board, screen, notes) goes through `DottieMathText.pretty` (math and chemistry symbols) and can carry `DottieInkText` markings: `{red:…}`, `{highlight:…}`, `**bold**`.
- **Live meeting help**: while meeting mode runs, `DottieMeetingLiveHelp` feeds the mic ("You") and the Mac's audio ("Them") separately from `MeetingAudioMixer` into two Apple speech recognitions; a 0.7 s pause ends what someone said. When "Them" ends with a question (or ⌘⇧Return / the notch's "help me"), the last 2 minutes, the user's prep notes and a screenshot only when the screen changed (32×18 fingerprint) go to `/chat` with `"provider": "groq"`, and two or three short lines show in the notch's `.meetingHelp` card, never spoken. Talking points refresh every 30 s; asks are capped at 8 a minute.
- **Groq (mixed with Gemini)**: voice (Live), TTS and dictation stay on Gemini. `/chat` bodies with `"provider": "groq"` (live help, `DottieChat` text-only asks, the guesser's plan, pointing refinement, guides' Gemini fallback and screen-job steps) go to Groq first when `GROQ_API_KEY` is set and the request fits (`GROQ_MAX_REQUEST_TOKENS`, 7000 for the free plan; screen jobs send Groq only their 3 newest screenshots and recent steps via `fittedForProvider`), then Gemini; Dot turns (`/gemini/*` generateContent) that fit go to Groq first too. Groq is asked for boxes in pixels and its answer turned back into `box_2d` (`pixelBoxConversion`). Other small `/chat` requests get Groq as a backup. `worker/src/chatCompletions.ts` converts Gemini bodies to OpenAI chat format for Groq and NIM, and gives their function calls the placeholder thought signature.
- **Model names**: set on the Worker in `wrangler.toml` `[vars]`, not in the app
- **Screen Capture**: ScreenCaptureKit (macOS 14.2+), multi-monitor support
- **Voice Input**: Push-to-talk via `AVAudioEngine` + pluggable transcription-provider layer. System-wide keyboard shortcuts (talk and dictation, both recordable in Settings) via a CGEvent tap.
- **Element Pointing**: In live mode, all displays are drawn side by side into one frame (`captureCompositeFrameForLive`); Gemini's `point_at_element(x, y, label)` is resolved back to a display and converted to AppKit coordinates. In classic mode the model embeds `[POINT:x,y:label:screenN]` tags. Either way the blue cursor animates along a bezier arc to the target.
- **Concurrency**: `@MainActor` isolation, async/await throughout
- **Analytics**: PostHog via `ClickyAnalytics.swift`, off unless `PostHogAPIKey` is set in Info.plist

### API Proxy (Cloudflare Worker)

The app never calls external APIs directly. All requests go through a Cloudflare Worker (`worker/src/index.ts`) that holds the real API keys as secrets.

| Route | Upstream | Purpose |
|-------|----------|---------|
| `POST /live-token` | `generativelanguage.googleapis.com/v1beta/auth_tokens` | Single-use Gemini Live ephemeral token (session must start within 2 min) |
| `POST /chat` | `…/models/{model}:streamGenerateContent?alt=sse` | Gemini vision + streaming chat (onboarding demo, classic mode) |
| `POST /dictate` | `…/models/{dictation model}:generateContent` | Hold-to-dictate: a WAV recording in, cleaned-up text out, in one call |
| `POST /tts` | `…/models/{tts model}:generateContent` | Gemini TTS, returned as raw 24kHz PCM (classic mode) |
| `* /gemini/*` | `generativelanguage.googleapis.com/*` | Passthrough for Gemini CLI (agents). The CLI sends the shared secret as its API key; the Worker swaps in the real one |
| `GET /search?q=` | Bing, DuckDuckGo, Wikipedia | Free web search (Google Search grounding is quota-blocked on free keys): asks Bing and DuckDuckGo at once and keeps the results covering the most of the question; `debug=1` shows each engine |
| `GET /config` | none | Echoes the configured model names |
| `POST /phone/pair`, `/phone/unpair`, `/phone/telegram/<method>` (incl. `/phone/`) | Telegram Bot API, `PhoneRelay` Durable Object | Dottie's own phone bot (`worker/src/phoneRelay.ts`): one-tap pairing link, each Mac's mailbox (long-polled getUpdates) and sends forced to its paired chat. The Mac signs with its install key (`x-dottie-phone-key`) |
| `POST /telegram/webhook` | none | Telegram's webhook for Dottie's bot (secret token derived from the bot token), set by the first `/phone/pair` |
| `GET /health` | none | Says whether the Worker is up and has a Gemini key (the release workflow checks it after deploying) |

Worker secrets: `GEMINI_API_KEY`, optional `APP_SHARED_SECRET` (checked against the `x-clicky-secret` header; `/gemini/*` takes it as the API key), optional `GROQ_API_KEY` (quick asks, pointing, screen jobs and Dot turns that fit go to Groq first) and `NVIDIA_API_KEY` (NIM backup models, used only when every Gemini model is busy); both through `worker/src/chatCompletions.ts`; optional `TELEGRAM_BOT_TOKEN` (Dottie's own phone bot for one-tap pairing; its mailboxes are the `PHONE_RELAY` Durable Object binding, SQLite-backed so it works on the free plan)
Worker vars: `GEMINI_LIVE_MODEL`, `GEMINI_CHAT_MODEL`, `GEMINI_HIGHER_MODEL` (send_to_higher_model), `GEMINI_TTS_MODEL`, `GEMINI_TTS_VOICE`, `GEMINI_DICTATION_MODEL`, `GEMINI_FALLBACK_MODELS` and `GEMINI_TTS_FALLBACK_MODELS` (tried in order when a model is busy), `GROQ_TEXT_MODELS`, `GROQ_VISION_MODELS`, `GROQ_MAX_REQUEST_TOKENS`, `NIM_MODELS`

App Info.plist keys: `ClickyWorkerBaseURL`, `ClickyAppSharedSecret`, `CompanionVoiceMode`, `OnboardingVideoURL`, `PostHogAPIKey`, optional `PostHogHost`, `GeminiCLIPath`, `GeminiAgentModel`, `CuaDriverPath`, `DottieUpdateRepository`, `MausBotHelperModel` and `MausBotGameModel`

### Key Architecture Decisions

**Menu Bar Panel Pattern**: The companion panel uses `NSStatusItem` for the menu bar icon and a custom borderless `NSPanel` for the floating control panel. This gives full control over appearance (dark, rounded corners, custom shadow) and avoids the standard macOS menu/popover chrome. The panel is non-activating so it doesn't steal focus. A global event monitor auto-dismisses it on outside clicks.

**Cursor Overlay**: A full-screen transparent `NSPanel` hosts the blue cursor companion. It's non-activating, joins all Spaces, and never steals focus. The cursor position, response text, waveform, and pointing animations all render in this overlay via SwiftUI through `NSHostingView`.

**Global Push-To-Talk Shortcut**: Background push-to-talk uses a `CGEvent` tap instead of an AppKit global monitor so modifier-based shortcuts like `ctrl + option` are detected more reliably while the app is running in the background. The talk and dictation shortcuts are `ClickyHotkey` values (modifiers only, optionally one side's key, or modifiers + a key) saved in UserDefaults and recorded in Settings by `ClickyHotkeyRecorder`. With Accessibility the tap is active so it can swallow a key shortcut's key; without it the tap only listens.

**Live audio through the dictation pipeline**: `BuddyDictationManager` already owns the mic, permissions, waveform and press/release lifecycle. In live mode it is constructed with `GeminiLiveCompanionTranscriptionProvider`, which forwards mic buffers (batched to ~100ms of 16kHz PCM16) to the Live session instead of a speech-to-text service. The spoken answer comes back through `GeminiLiveVoiceClient`'s callbacks, not the dictation callbacks.

**Live session lifecycle**: Sessions with video input are capped at about two minutes, so the socket opens on the first press, closes after 45 idle seconds or on `goAway`, and the last ten exchanges (from Live's input/output transcriptions) are appended to the next session's system instruction. Messages sent before `setupComplete` are queued so the user can talk immediately. A 20s watchdog drops a silent connection.

**Shared URLSession**: Long-lived `URLSession`s are owned by the clients, not per request. Creating and invalidating a URLSession per session corrupts the OS connection pool and causes "Socket is not connected" errors after a few rapid reconnections.

**Native look, light and dark**: Home and the menu bar panel follow the system appearance (native macOS look: system font, sidebar material, accent #0066CC). `DS.Colors` tokens are adaptive `NSColor`s, so surfaces that must stay dark (the notch, cursor overlay, response panel, annotation windows) set `NSAppearance(named: .darkAqua)` on their window. Buttons use `.pointerCursor()` (cursor rects), not `NSCursor` push/pop, which could leave the hand cursor stuck.

**Dynamic Island notch**: The notch panel is one black `DottieIslandShape` that grows out of the hardware notch. Idle it is closed (or shows small wings for unread Dots), listening and thinking open wings beside the notch (eyes + waveform or dots), and everything else (captions, answers, the hover peek, permission and screen-task cards) expands into a card below it with a spring. The window is sized per `IslandPresentation` so it only covers what is drawn.

**Transient Cursor Mode**: When "Show Dottie" is off, pressing the hotkey fades in the cursor overlay for the duration of the interaction (recording → response → TTS → optional pointing), then fades it out automatically after 1 second of inactivity.

## Code Style & Conventions

### Variable and Method Naming

IMPORTANT: Follow these naming rules strictly. Clarity is the top priority.

- Be as clear and specific with variable and method names as possible
- **Optimize for clarity over concision.** A developer with zero context on the codebase should immediately understand what a variable or method does just from reading its name
- Use longer names when it improves clarity. Do NOT use single-character variable names
- Example: use `originalQuestionLastAnsweredDate` instead of `originalAnswered`
- When passing props or arguments to functions, keep the same names as the original variable. Do not shorten or abbreviate parameter names. If you have `currentCardData`, pass it as `currentCardData`, not `card` or `cardData`

### Code Clarity

- **Clear is better than clever.** Do not write functionality in fewer lines if it makes the code harder to understand
- Write more lines of code if additional lines improve readability and comprehension
- Make things so clear that someone with zero context would completely understand the variable names, method names, what things do, and why they exist
- When a variable or method name alone cannot fully explain something, add a comment explaining what is happening and why

### Swift/SwiftUI Conventions

- Use SwiftUI for all UI unless a feature is only supported in AppKit (e.g., `NSPanel` for floating windows)
- All UI state updates must be on `@MainActor`
- Use async/await for all asynchronous operations
- Comments should explain "why" not just "what", especially for non-obvious AppKit bridging
- AppKit `NSPanel`/`NSWindow` bridged into SwiftUI via `NSHostingView`
- All buttons must show a pointer cursor on hover
- For any interactive element, explicitly think through its hover behavior (cursor, visual feedback, and whether hover should communicate clickability)

### Do NOT

- Do not add features, refactor code, or make "improvements" beyond what was asked
- Do not add docstrings, comments, or type annotations to code you did not change
- Do not try to fix the known non-blocking warnings (Swift 6 concurrency, deprecated onChange)
- Do not rename the project directory or scheme (the "leanring" typo is intentional/legacy)
- Do not run `xcodebuild` from the terminal — it invalidates TCC permissions

## Git Workflow

- Branch naming: `feature/description` or `fix/description`
- Commit messages: imperative mood, concise, explain the "why" not the "what"
- Do not force-push to main
